# 任务执行页面设计规格

日期：2026-10-16  
状态：待用户审阅  
范围：在 Import Desk 中集中执行现有采集、入库和定时任务；不开放任意命令执行。

## 1. 背景与现状

- 前端使用 React 18、Ant Design 4 和 React Router，页面挂在 `/app` 的 `AppLayout` 下。
- 后端使用 Koa，监听 8081；现有 API 未实现任务执行或任务控制权限。
- `package.json` 包含 ImportGenius 抓取、入库、定时任务，以及 ImportYeti CLI 等业务脚本。ImportGenius 的抓取脚本存在硬编码国家选择；其中部分脚本仅导出函数，直接运行 npm script 并不能保证实际执行任务。
- `importgenius/schedule/getData.js` 使用 `node-cron`，周日 00:00 执行，并在进程启动时立即执行一轮；`pm2.config.js` 将它作为独立进程管理。
- `stock-watch` 的任务页提供任务目录、状态标签、立即执行/启停操作、最近运行信息、详情响应和定时刷新。本设计复用这些交互思路，并确保状态来自真实任务运行状态。

## 2. 用户目标

用户可在页面找到业务任务、查看当前执行环境、填写必要参数并启动任务。定时任务可从页面查看、启动、停止，并能看到最近运行状态。相同页面部署到本地和生产时，只能操作该部署后端所配置的数据源；生产操作需要二次确认。

## 3. 方案与决策

### 方案 A：后端白名单任务管理器（采用）

后端维护固定任务目录、参数校验、运行状态和 Cron 实例。页面提交 task ID 与结构化参数。长任务异步运行并回传 run ID，页面轮询状态与日志。定时任务归任务管理器所有。

优点：环境、命令和参数均由后端控制；运行状态与真实执行器关联；前端不需要知道服务器路径或 shell 命令。

### 方案 B：通用 shell 执行接口（不采用）

页面将 npm 命令交给后端运行。虽可快速接入脚本，但会暴露任意命令执行面，参数注入和环境误操作风险高，也难以定义准确的任务状态。

### 方案 C：保留独立 PM2 定时器并从页面控制 PM2（不采用）

页面通过 PM2 命令管理定时器。该方式要求 Web 服务拥有进程管理权限，且进程状态、调度状态和页面实例可能不一致。

## 4. 页面设计

### 4.1 路由与导航

- 新增 `/app/tasks` 页面和“任务执行”侧边栏入口。
- 页面沿用现有 `PageHeading`、卡片、Ant Design 标签和按钮样式。
- 页头从后端状态接口读取环境徽标：本地、生产或未配置。环境未配置时所有执行和启停操作禁用。

### 4.2 任务目录

按业务分组展示任务卡片；卡片说明用途、副作用、必要参数、最近执行状态，并提供允许的操作。

**ImportGenius**

- 抓取 importer 列表：国家与页码/页码范围。
- 抓取 shipment 详情：国家与页码/页码范围。
- 批量导入数据库：国家与待导入页码。
- 完整采集流程：国家范围和采集上限；按抓取列表、详情补充、数据库导入顺序执行。
- 周定时任务：立即运行、启动定时、停止定时。

完整流程与单步任务同时提供。定时器执行完整流程，不调用付费 API。

**ImportYeti**

- 初始化数据库结构。
- 执行爬取：最大目标数、最大关系深度、请求间隔、是否重试失败项。
- 查看采集状态。
- 导出 CSV：输出文件名限制在项目导出目录内。

不在页面中暴露 `build`、`test`、`server` 或任意其他开发运维脚本。

### 4.3 状态与操作

- 任务状态至少区分：未运行、运行中、成功、失败、未知。
- 定时器启停状态独立展示：已启用/已暂停；同时显示运行中的执行状态与最近一次运行结果，避免把“定时已启用”误解为“正在执行”。
- 定时器卡片显示 Cron 表达式、时区、下次运行时间、最近开始/结束时间、耗时和错误摘要。
- 任务详情展示最近输出与错误；长输出截断并支持查看尾部日志。
- 当前页面会话中的任务状态每 30 秒刷新；页面隐藏时暂停轮询，重新显示后立即刷新。
- 同一任务运行时禁用重复启动；后端也必须拒绝并发重复执行。
- 生产环境的写库、外部请求、定时器启停均需二次确认；生产 API 同时校验 `TASK_CONTROL_TOKEN`。令牌由服务端配置，页面在当前会话中提交，不从 URL 或任务参数读取。

## 5. 环境与安全规则

- 使用显式 `TASK_ENV=local|production` 标识后端运行环境；本地启动脚本显式设置为 `local`，生产部署必须设置为 `production`。
- 环境来自后端配置，不根据浏览器 hostname、请求参数、前端构建模式或用户选择推断。
- `TASK_ENV` 缺失/非法时，状态 API 返回 `unknown`，所有任务操作拒绝执行。
- 任务参数由后端按 task ID 校验和限幅；国家必须在对应环境的允许列表中，页码、页数、深度、请求间隔设置上限。
- ImportGenius 数据库环境映射只在服务端发生：`local -> ENV=dev`，`production -> ENV=production`。客户端不能覆盖环境变量或数据库配置。
- 后端维护 task ID 到固定任务处理器/固定脚本路径的映射；使用参数数组和 `shell: false`，不拼接命令字符串，不执行客户端传来的命令。
- 生产路由未配置控制令牌时拒绝写操作；错误信息不回显令牌、密码或完整环境变量。

## 6. 后端执行架构与数据流

1. 页面调用任务目录/状态接口，获得后端环境、允许任务、任务状态与定时器状态。
2. 页面通过 task ID 和 JSON 参数请求执行。后端检查环境、令牌、任务定义、参数和并发锁。
3. 后端创建 run ID，将状态设为运行中，并通过固定处理器执行任务。长任务使用子进程时只启动固定 Node 脚本路径和经过验证的参数，捕获 stdout/stderr；不得使用 shell。
4. 任务结束后记录成功/失败、开始/结束时间、耗时、摘要及有上限的日志尾部。运行失败时保留错误状态，不报告成功。
5. 页面通过状态查询接口获取运行变化和最近输出。

建议 API：

- `GET /api/tasks`：环境、任务目录、状态、服务端时间。
- `POST /api/tasks/:taskId/run`：启动一次性任务，接受结构化参数，返回 `runId`。
- `GET /api/tasks/:taskId/runs/:runId`：获取状态、时间、结果摘要和日志尾部。
- `POST /api/tasks/:taskId/scheduler`：`start` 或 `stop` 定时器。

所有写接口要求同源请求；生产写接口另校验控制令牌。响应包含明确状态码和错误类型，不能用空响应代表运行成功。

## 7. 定时器管理

- 将周定时器注册到任务管理器，由后端的 `node-cron` 实例提供真实启停状态；移除独立 PM2 定时器配置，确保生产只有一个调度所有者。
- 保留周日 00:00 调度，明确时区为 `Asia/Shanghai`。
- 生产服务启动时注册并启用 Cron，但不因进程重启立即额外执行一轮；需要立即执行时由页面按钮触发。
- 本地服务启动时不自动启用 Cron；用户可从任务页手动启动。
- 当前版本的定时器期望状态和运行注册表保存在服务进程内存中；服务重启后按环境默认重新注册，运行中任务显示为未知/已中断，而不是伪造成功。历史运行持久化不作为第一阶段要求。
- 任务目录返回 Cron 表达式及下次执行时间。下一次时间必须基于明确时区计算。

## 8. 错误与边界情况

- 环境未配置：只读显示状态，执行 API 返回环境配置错误。
- 未授权或缺少生产令牌：拒绝操作，页面提示需要配置任务控制权限。
- 参数无效、未知任务 ID、国家不允许：拒绝并返回可读字段错误，不启动子进程。
- 同一任务运行中：返回冲突状态，不重复执行。
- 子进程启动失败、非零退出或超时：状态标记失败，保留退出码/错误摘要/日志尾部。
- 后端重启导致状态丢失：当前任务显示未知/中断；Cron 状态以重新注册后的真实实例为准。
- 状态接口不可达：页面展示接口异常，不用本地点击状态冒充服务端状态。
- 生产任务运行中不提供强制杀进程操作；停止定时仅阻止未来触发，不中断当前运行。

## 9. 验收与验证场景

- 本地页面只返回本地配置和任务集合；无法通过请求参数切到生产。
- 生产页面返回生产环境标记；没有令牌、令牌错误、任务 ID 非白名单时，写操作被拒绝。
- 未知环境、未知任务、无效页码/国家、并发重复启动均不执行任务。
- 手动任务能从排队/运行进入成功或失败，显示开始/结束时间、耗时及相应日志摘要。
- 启停定时器后状态与 `node-cron` 实例一致；停止只影响未来触发。
- 周 Cron 显示的时区与下次触发时间一致；服务重启不触发立即抓取。
- 单步采集、完整流程、ImportYeti 命令均使用页面提交的参数和当前后端环境。
- 页面轮询、隐藏暂停、恢复刷新、状态接口错误和生产二次确认均可验证。

## 10. 不在本次范围

- 不接入 ImportGenius 付费 API。
- 不开放任意 shell、任意 npm script 或任意文件路径执行。
- 不新增复杂的多用户角色和任务编排工作流。
- 不持久化跨进程/跨部署的任务历史；第一版状态范围是当前服务运行周期。
- 不改变采集策略、关键词匹配或 ImportYeti 的抓取规则，除非为了让现有任务接受经过校验的页面参数而需要做窄范围适配。

## 11. 自审记录

- 任务范围已限定为现有业务抓取、入库、导出和定时任务；开发工具脚本明确排除。
- 前端环境选择、任意命令、未授权生产写操作均被禁止。
- 定时器“启用状态”和“最近执行结果”分开，避免状态语义冲突。
- Cron 重启行为明确为重新注册但不立即执行；本地默认停、生产默认启用。
- 生产控制令牌需要在部署环境配置；未配置时生产写操作不可用。
- 当前服务重启后的状态语义和第一版不持久化历史已写明。
