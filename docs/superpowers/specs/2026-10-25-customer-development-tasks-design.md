# 客户开发任务控制台

日期：2026-10-25。用户已确认将页面接入 import-data，继续使用 my-robot 的任务脚本。

## 目标与范围

新增 `/app/robot-tasks` 与“客户开发任务”导航。沿用 React 18、Ant Design 4、Koa 的任务运行、终止及持久化日志体系，新增 Facebook、Instagram、TikTok、Gmail 和诊断分类。保留现有采集任务、数据库任务及定时器行为。本次仅手动运行客户开发任务，不创建新的自动调度。

任务标题必须准确描述业务动作。任务卡说明用途、名单来源、筛选条件、处理步骤、外部动作、输出位置、前置条件、批次限制、完成判据和局限；展开详情提供完整说明。现有关注脚本不得称为纯客户采集；邮件预约不得称为已投递；历史 hasUsed/hasChated 仅为旧标记。Android、会重置状态的名单工具和未完成的网站检查显示能力缺口，不伪装为可执行功能。

## 架构与接口

- 后端固定目录 `server/robot/` 管理任务定义、服务端根目录解析、检查及执行桥接。目录由 `MY_ROBOT_ROOT` 指定；本机兼容 Documents/import-data 与 Documents/bot/my-robot 的布局。浏览器不传路径、脚本、shell 或环境配置。
- 任务 ID 固定为 `robot.inspect`、`robot.facebook.expand/chat`、`robot.instagram.expand/chat`、`robot.tiktok.expand/chat`、`robot.email.first/second/third`。经现有 `/tasks` 接口执行和查询，运行历史写入现有 logs/tasks。
- GET /tasks 新增 robot 集成状态，并为客户开发任务提供 platform、readOnly、sourceScript、inputs、outputs、steps、effects、prerequisites、limitations、batchLimit、supported、disabledReason 元数据。任务名和描述由后端单一来源提供。
- 客户开发任务接受空参数；有外部动作的任务必须传 `acknowledged: true`，后端校验。首版不展示脚本尚未支持的自定义数量或间隔控件。沿用环境、同源和生产令牌校验。
- 固定 worker 在同一个子进程内调用 my-robot 导出的 startApp，避免产生无法终止的孙进程。旧 CLI 入口继续可用；require 模块不自动启动。异常必须导致失败退出码，统一 finally 释放 driver。
- 所有任务共享现有全局运行锁；my-robot 桥接增加磁盘互斥锁防止不同服务实例同时操作同一浏览器/名单。运行中终止只终止此 worker，不对任意 PID 操作；已发生的外部动作无法撤销，结果不明确时需核对。
- 诊断仅读取固定 JSON 格式名单，汇总历史标记、候选数、重复与冲突，不返回客户原始数据，不执行名单 JS、不连接浏览器。目录缺失或脚本未适配时按任务返回明确不可执行原因。
- 浏览器动作日志脱敏后写入现有日志服务，不暴露凭据和客户邮箱。运行完成只表示脚本流程结束，无法证明关注成功或邮件送达。

## 必要兼容修复

my-robot 的九项 Web/邮件入口提供 awaitable startApp 和明确错误传播；修正 Facebook 浏览器作用域文件写入及异步遍历，IG/TT 异步遍历；私信与邮件执行返回失败或跳过时不推进成功标记。名单写入改为同目录临时文件后重命名。未知邮件国家使用默认时间，预约日期避开周末。只修改接入所必需代码，不回写任何真实客户状态。

## 页面与优化分析

页头显示实际后端环境、集成可用性、运行任务数量和只读诊断入口。按平台切换、关键词查找任务；卡片可展开任务流程及输入输出。执行前展示具体动作和确认勾选；生产继续要求令牌。运行中轮询真实状态，显示运行日志及历史详情入口，页面隐藏暂停轮询。服务错误提供重试，不显示模拟数据。

“优化分析”页签按平台和优先级展示项目证据、当前问题、建议、收益与验收点：P0 结果状态/文件覆盖/共享会话；P1 线索与动作分离、稳定 ID 去重、筛选解释、断点恢复、停止跟进、时区与 Gmail API；P2 线索评分、模板实验和有效线索转化指标。官方能力边界与来源链接并列，规划能力明确标注。

## 验收

1. 原有任务页和日志页可继续使用，新页面所有任务文案准确、可展开、可检索。
2. 不可用目录、缺失入口、未确认动作、未知参数和未配置环境均不执行脚本；生产权限沿用现有规则。
3. 模拟 worker 验证启动、失败、终止、互斥、脱敏和日志留存；诊断只用临时脱敏名单验证。
4. 前端交互测试覆盖分类/检索、确认、禁用原因、执行、终止和运行错误；构建通过并进行浏览器检查。
5. 验证过程中不运行真实关注、私信或邮件发送；真实平台页面 DOM、登录及预约结果需要部署后由操作者小批量核验。
